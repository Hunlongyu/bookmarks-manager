# 书签管理器功能清单

更新日期：2026 年 11 月 3 日

书签管理器用于按需导入、整理、检查和清理浏览器书签，再导出 HTML 或覆盖写回浏览器。每次启动建立新的整理会话，配置和网页分析缓存保存在本机，方便下次复用。

本清单替代旧版候选功能池。清单依据本轮已确认范围整理，并补充完成流程所需的基础能力；P0、P1、P2 是开发顺序建议。当前工程仍为 Wails 基础骨架，表中的功能是待开发范围。软件自升级已确认纳入，并安排在全部业务功能之后开发。

## 产品范围

| 项目 | 确定范围 |
| --- | --- |
| 首个验收平台 | Windows。 |
| 浏览器 | Chrome、Edge、Firefox，支持识别并选择用户配置；其他浏览器不纳入适配。 |
| 数据接入 | 直接读取浏览器本地书签；导入浏览器书签 HTML。 |
| 数据输出 | HTML 导出；关闭目标浏览器并完成备份后覆盖写回。 |
| 多浏览器输出 | 一次手动操作，可将同一份整理结果写入一个或多个选中的浏览器用户配置。 |
| 写入模式 | 仅覆盖写入。合并在软件工作区中完成，浏览器写入界面不提供追加合并模式。 |
| 工作区 | 一个当前会话，保留来源目录、原始层级和顺序，不设置独立的多个书签库。 |
| 使用方式 | 桌面端软件，不制作手机界面，桌面窗口可自由缩放；默认进入工作区，不显示模式名称或切换，所有检查和 AI 分析均由用户主动发起。 |
| 数据保存 | 单 EXE 分发；AppData 保存配置、数据库、SEO 与 AI 缓存、图标和临时文件。备份固定保存到 `%APPDATA%\BookmarksManager\backups`，不提供其他保存目录。 |
| 会话结束 | 下次启动重新导入；不恢复上次的工作区和回收站。启动时自动加载默认目录中的备份列表，由用户选择恢复。 |
| 性能规模 | 以 1 万条以内书签作为主要性能验收范围。 |
| 技术栈 | Go + Wails v3.1.0；React + TypeScript + Vite + pnpm + Radix Themes。Go 负责任务、网络、AI 和数据处理。 |

浏览器扩展、独立多库、撤销与重做、CSV 或通用 JSON 导入入口、报告文件导出均不在本轮范围内。内部解析浏览器 JSON 或 SQLite 文件属于浏览器适配，不属于新增用户导入格式。

## 优先级建议

| 优先级 | 目标 | 主要范围 |
| --- | --- | --- |
| P0 | 完成一次可靠的书签清理 | HTML 与三种浏览器接入、手动整理、去重、快速检查、基础修复、备份恢复、覆盖写回、流畅交互。 |
| P1 | 提高理解、检索和分类能力 | 规则内容检查、统一 AI 分析、标签与缓存复用、AI 搜索、AI 目录整理、多套 AI 配置。 |
| P2 | 网站发现与最后阶段升级 | 基础相似网站推荐、可选联网推荐、搜索服务接入与结果验证；软件自升级安排在最后。 |

P1 和 P2 中已确认的功能仍属于新版范围。分期用于让每一阶段都可独立验收，不把“后做”解释成取消需求。

## 会话与本地数据

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| BAS-01 | 当前整理会话 | 每次启动从新会话开始。导入后保留原目录、顺序和来源，提供当前工作区的统一操作范围。 | P0 |
| BAS-02 | 配置持久化 | 保存检查、代理等配置；AI 配置随 AI 功能接入。配置和数据库放在 AppData。 | P0 |
| BAS-03 | 分析缓存 | 持久保存 SEO、页面内容摘要、AI 分析版本及时间、favicon 等。再次导入对应页面时复用有效结果。 | P0 |

缓存中的历史网址不会自动成为当前工作区书签。搜索、分类和写回仅作用于本次导入或主动添加的书签。新的 URL、过期或信息不足的分析应显示状态，并提供手动刷新入口。

| --- | --- | --- | --- |
| IN-01 | HTML 导入 | 读取浏览器导出的书签 HTML，处理目录、标题、URL 和能够识别的附加信息。 | P0 |
| IN-02 | Chrome 与 Edge 直接读取 | 发现浏览器及用户配置，展示可读取的书签范围，再导入当前会话。 | P0 |

| IN-05 | 导入预览与结果 | 展示来源、数量、结构和异常项；取消预览不改变工作区，执行后可查看成功、跳过、失败及原因。 | P0 |

同一浏览器有多个用户配置时，来源信息应足以区分配置。系统根目录、账号书签和本地书签按实际读取结果展示，不凭目录名称将它们当成同一个范围。

## 去重与空目录清理

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| DUP-01 | 完全重复检测 | 按保存的完整 URL 相同分组，支持跨目录查看，用户决定保留一条、多条或全部。 | P0 |
| DUP-02 | 疑似重复检测 | 对确定的跟踪参数差异、不同地址跳转到同一页面等生成候选，展示依据，逐项或批量确认。 | P0 |
| DUP-03 | 空目录清理 | 检查空目录及递归为空的目录子树，预览后移入回收站；保留浏览器系统根目录。 | P0 |

不将整个域名下的不同页面合并为一条书签；不通过删除未知参数、统一路径大小写或随意截掉 URL 片段来认定重复。地址修复产生的新重复项重新提示，由用户决定。

## 检查与网络设置

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| NET-01 | 连接方式与代理 | 支持直连、系统代理、自定义 HTTP 或 SOCKS5 代理，保存配置并提供连接测试。 | P0 |
| NET-02 | 快速可访问检查 | 对选中书签、目录或全部书签检查，区分可访问、疑似失效、访问受限、超时、DNS 错误和其他失败。 | P0 |
| NET-03 | 重定向记录与更新 | 展示原地址、跳转链、永久或临时类型、最终地址与最终访问状态；提供单项和批量更新，确认后应用。 | P0 |
| NET-04 | 任务控制 | Go 执行有界并发、超时和有限重试；展示进度，支持暂停、继续、取消及只重试失败项。 | P0 |
| NET-05 | 规则内容检查 | 可选检查停站、域名出售、停放页等内容，给出命中依据和不确定性，不消耗 AI Token。 | P1 |
| NET-06 | AI 深度检查 | 用户勾选后分析页面是否正常；既可复查疑似问题，也可选择全部页面深度检查，复用统一 AI 分析结果。 | P1 |

配置并验证可用的在线 AI 或本地模型后，才开放 AI 检查选项；配置成功不会自动启动分析。快速检查、规则检查和 AI 检查分别显示覆盖范围，未执行的检查不能显示为“正常”。

HTTP 可访问与页面内容正常分别记录。访问受限、需要登录、反爬或网络失败不直接判定为永久失效。检查结论提供依据，删除操作仍由用户选择。

检查、元数据获取、favicon 和在线 AI 使用统一的网络配置。连接本地模型时明确本机直连行为，避免把本地服务请求误送到远程代理。

## 基础修复与页面信息

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| FIX-01 | 标题修复 | 获取可用的网页标题，展示现有标题与建议标题，支持单项和批量确认。 | P0 |
| FIX-02 | favicon 修复 | 获取、刷新并缓存网站图标；获取失败时提供默认图标。 | P0 |
| FIX-03 | 跟踪参数清理 | 仅对明确的跟踪参数提出删除建议，预览原 URL 和建议 URL，确认后应用，修改前建立备份。 | P0 |
| META-01 | SEO 信息获取 | 保存页面标题、描述、Open Graph 信息及必要的有限正文片段，为修复和后续 AI 分析提供输入。 | P0 |

未知参数、业务参数、登录信息和签名 URL 保守保留，不能因为某个参数看起来复杂就删除。

favicon 修复首先保证软件中的图标显示和缓存。浏览器原生图标存储的写入能力需单独适配验证，不将普通书签写回描述成已经同步浏览器 favicon。

页面信息获取由用户选择的操作触发。只做可访问检查时采用轻量流程；需要标题、SEO 或 AI 分析时尽量合并同一页面的必要获取工作。

## AI 配置与统一分析

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| AI-01 | 在线服务与本地模型 | 支持配置 API 地址、密钥和模型，或连接本地模型服务；调用由 Go 负责。 | P1 |
| AI-02 | 多套 AI 配置 | 保存多套配置，可命名、测试连接并手动切换；每次任务使用选中的配置。 | P1 |
| AI-03 | 一次统一页面分析 | 同一次页面分析返回页面状态、用途或摘要、规范化标签及判断依据，为后续功能共享。 | P1 |
| AI-04 | 手动批量分析与复用 | 点击后分析选中项、目录或全部书签，展示待分析和可复用数量，支持暂停、取消与主动重新分析。 | P1 |
| AI-05 | 隐藏的用途标签 | 标签保存在软件数据库，供搜索与分类使用；主界面不铺开标签，不要求逐条手工标记。 | P1 |

一次页面分析同时完成健康判断、用途说明和标签提取，不为这些用途分别重复请求同一页面。已有 SEO 和 AI 结果优先复用；切换配置不会自动重新分析全部页面。

同一 URL 在多个目录出现时，书签仍保留多条，页面分析可以共享。相同域名下的不同页面不能直接共用同一份页面结论。缓存保存分析时间、输入版本和所用模型，失败结果不冒充成功分析。

AI 搜索的查询理解、目录建议和外部网站推荐可能产生新的请求；这些请求读取已有页面分析，不重新批量抓取和分析所有页面。一次页面分析不等于以后所有 AI 功能均不再产生调用。

## 搜索与 AI 目录整理

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| SRCH-01 | 普通搜索与筛选 | 按标题、URL、域名、路径及已保存描述查找，结合目录和检查状态筛选。 | P0 |
| SRCH-02 | AI 自然语言搜索 | 用“找出所有 icon 图标网站”等需求搜索本次工作区，综合 SEO、用途标签和已有分析。 | P1 |
| SRCH-03 | 完整结果与覆盖提示 | 展示匹配理由、所在目录和结果数量，支持完整列表或分页，说明未分析、信息不足等可能遗漏。 | P1 |
| CAT-01 | 沿用现有分类 | 根据已有目录推荐书签位置，必要时提出新增目录建议。 | P1 |
| CAT-02 | 重新规划分类 | 根据所选书签用途生成新的目录结构与归类建议。 | P1 |
| CAT-03 | 分类建议预览与应用 | 显示原路径、新路径和新建目录，可选择部分建议，确认后先备份再执行；手动调整与合并继续可用。 | P1 |

AI 搜索结果必须对应当前工作区实际存在的书签，不添加未收藏网址，也不把缓存里上次导入的站点当成本次结果。搜索目标是尽量找全相关书签，覆盖不足时明确提示，不能无依据宣称“全部找到”。

## 相似网站推荐

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| REC-01 | 基础推荐 | 右键网站书签，根据用途和模型已有知识生成相似网站候选，再检查网址与用途，标明未经过联网检索的来源方式。 | P2 |
| REC-02 | 可选联网推荐 | 通过模型服务已接入的联网能力或独立搜索 API 查找候选，再由 AI 筛选；搜索服务配置可保存。 | P2 |
| REC-03 | 推荐复核与保存 | 显示推荐理由、信息来源、检查状态和是否已收藏；去除重复候选，仅将用户选中的网站加入指定目录。 | P2 |

基础推荐不虚构搜索来源；可访问也不等于用途已经核实。推荐中“免费”“免注册”等条件缺乏依据时标为未核实。联网推荐没有可靠候选时说明结果不足，不凑数。

填写通用模型 API 不代表已经获得联网搜索能力。接入时按模型服务能力或独立搜索服务分别验证。部分模型服务提供搜索工具，独立搜索服务也提供单独的 API，二者需要各自的配置与错误处理。[模型服务搜索文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)、[搜索服务 API 文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

## 回收站与备份恢复

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| SAFE-02 | 会话回收站 | 删除书签和目录先进入回收站，可恢复原内容及层级；与当前会话一同结束。 | P0 |
| SAFE-03 | 手动备份与恢复 | 可主动创建备份；批量删除、合并、覆盖写回等操作前建立可恢复备份，失败则停止相应修改。备份固定保存在默认目录，启动自动加载列表；只从列表选择恢复，不提供打开任意备份文件或另存目录。 | P0 |

## 导出与浏览器覆盖写回

| 编号 | 功能 | 行为与边界 | 优先级 |
| --- | --- | --- | --- |
| OUT-01 | HTML 导出 | 输出全部、选定目录或所选书签的浏览器兼容 HTML；软件专有分析数据继续保存在本地。 | P0 |
| OUT-02 | Chrome 与 Edge 覆盖写回 | 关闭对应浏览器，备份后按确认的目标范围覆盖书签，保留目标格式所需的结构和元数据。 | P0 |
| OUT-03 | Firefox 覆盖写回 | 独立适配其数据库与书签结构，保留历史记录等非书签数据，提供同样的备份与恢复流程。 | P0 |
| OUT-04 | 多目标写回 | 可选择一个或多个浏览器用户配置，把同一份整理结果写入各目标，分别展示结果。 | P0 |
| OUT-05 | 写回前预检与预览 | 检查目标、版本或格式、关闭状态、后台进程、可写权限及读取后变化，预览新增、修改、移动和删除，再完成备份。 | P0 |
| OUT-06 | 写回校验与失败恢复 | 写入后重新读取并核对；失败时明确目标状态与可用备份，重试前复核，不能把部分成功显示成全部完成。 | P0 |

“覆盖”指替换预览确认的可写书签范围，不能覆盖整个浏览器用户目录。系统根目录、受管理项目和各浏览器的内部字段需分别处理。跨浏览器输出要预览目录落点，不能把源浏览器的内部标识直接复制为目标标识。

多目标不是一个跨浏览器事务：每个目标有独立的备份、写入状态和恢复入口。软件不直接修改浏览器账号云端数据；浏览器重新运行后的同步行为要纳入兼容测试。本地书签与账号书签可能同时存在，应明确实际目标。[Chrome 书签同步范围说明](https://developer.chrome.com/blog/bookmarks-sync-changes)。

| UX-01 | 统一工作区 | 启动直接进入工作区，按需执行导入、配置、检查、处理和输出；移除引导模式、步骤条与模式切换，不显示模式名称。 | P0 |
| UX-02 | 可选配置提示 | 按需填写 AI 和代理并测试连接；说明当前能够执行哪些检查，不将选配变成强制门槛。 | P0 |
| UX-03 | 结束页报告 | 不设常驻报告入口；完成整理、成功写回或导出 HTML 后显示本次导入、检查、修复、去重、移动和各目标结果，以及失败、跳过、未分析项。部分写回失败时留在处理页；不导出报告文件。 | P0 |
| UX-04 | 交互性能 | 1 万条以内书签时，检查期间仍可滚动、搜索、切换目录及操作任务；采用增量更新和适当的列表渲染方式。 | P0 |

AI 相关配置提示随 P1 能力开放。快速检查的完成数量、规则检查覆盖和 AI 分析覆盖分别展示，不能汇总为一个无法解释的“全部正常”。

导入后直接返回书签列表。用户可通过导航、工具栏和右键菜单执行任意已满足前置条件的操作，检查和输出均由用户主动发起，配置不再作为单独的引导步骤。左侧分列“写回浏览器”和“导出 HTML”，移除顶部笼统的“输出”入口；“AI 目录整理”继续保留。

桌面窗口不设固定尺寸或人为限定的最小宽高。导航、列表和详情随窗口大小调整，工具栏和表单根据可用空间换行，列表与详情独立滚动。较小的桌面窗口属于正常使用范围；不将“无需手机适配”解释为必须使用大窗口。

## 核心验收场景

| 场景 | 通过条件 |
| --- | --- |
| 原始结构保留 | 导入三种浏览器的样本后，层级、顺序、来源与支持字段正确，系统目录没有被当作空目录删除。 |
| 来源合并 | 同名目录合并内容且不自动改名，重复书签三种处理选择均能得到预览对应的结果。 |
| 新会话与缓存 | 重开软件没有上次工作区；配置仍在，再次导入相同页面可复用分析，旧缓存不会混入本次搜索。 |
| 基础整理闭环 | 导入、编辑、去重、检查、修复、HTML 导出均可完成，所有批量变更可按约定恢复。 |
| 错误分类 | 超时、403、DNS 错误、404、登录页、重定向分别有清楚依据；未检查项不计为正常。 |
| 地址修复 | 原地址和建议地址可比较；未知或重要参数保留；修改前备份可恢复，新增重复项可见。 |
| 页面分析复用 | 健康判断、用途和标签来自同一页面分析；搜索和分类不重新批量分析这些页面。 |
| AI 搜索 | 名称不带 icon 但用途明确的图标站能被检索；结果来自当前书签，信息不足显示覆盖限制。 |
| AI 分类 | 两种分类模式都能预览原路径与新路径、选择部分应用，修改前备份可恢复。 |
| 推荐保存 | 基础与联网推荐区分来源方式；只有主动选择的候选进入工作区。 |
| 浏览器写回 | 在独立测试用户配置验证关闭、备份、覆盖、重新启动读取与恢复；三种浏览器分别通过。 |
| 多目标部分失败 | 清楚显示每个目标的成功、失败或未执行状态，已成功目标不被盲目重复覆盖。 |
| 工作区与浏览器恢复 | 工作区备份恢复不改变浏览器数据；原浏览器通过对应备份和单独恢复流程还原。 |
| 1 万条响应 | 导入和检查时仍能执行常用交互，性能指标按开发计划中的测试条件实际记录。 |

实施顺序、依赖关系和阶段验收见[新版开发计划](新版开发计划.md)。
