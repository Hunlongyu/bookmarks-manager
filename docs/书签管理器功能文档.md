# 书签管理器功能文档

版本：0.10

整理日期：2026 年 10 月 31 日

更新日期：2026 年 11 月 2 日

状态：候选功能规划，供后续选择开发范围

书签管理器拟定位为**本地优先的桌面书签管理与清理工具**，既能整理浏览器导出的书签，也能作为独立书签库长期使用。主要解决书签分散、难以查找、重复积累、链接失效和迁移不便的问题。

功能池共包含 12 个领域、122 项候选功能。建议优先级分布为：P0 共 41 项，P1 共 48 项，P2 共 33 项。它们用于安排讨论和开发顺序，最终版本范围仍可按实际需求调整。

## 产品目标与使用场景

### 产品目标

- 无需账号即可在本地完成书签导入、管理、搜索、清理和导出。
- 将浏览器书签整理为长期可维护的个人资料库。
- 通过预览、确认、回收站和备份，降低批量整理时误删数据的风险。
- 将重复项和链接异常作为待处理线索，保留用户的判断和选择。

### 典型使用场景

| 场景 | 用户希望完成的事情 |
| --- | --- |
| 整理历史书签 | 导入浏览器导出的文件，保留目录，检查重复项和异常链接，再导回浏览器。 |
| 建立独立资料库 | 持续添加资料，按文件夹和标签分类，通过搜索快速找回。 |
| 合并多个来源 | 合并不同浏览器或不同时间的备份，预览冲突并决定保留方式。 |
| 定期清理 | 查找完全重复的 URL、空文件夹和疑似失效链接，逐项或批量处理。 |
| 数据迁移与恢复 | 导出浏览器兼容文件，或通过完整备份迁移和恢复书签库。 |

## 书签接入方式

产品提供手动文件和扩展连接两种方式，用户可按需选择。两种方式共用本地书签库和整理功能。

| 方式 | 将浏览器书签导入软件 | 整理后应用到浏览器 |
| --- | --- | --- |
| 手动文件方式 | 用户从浏览器导出 HTML，再在软件中选择或拖入文件。 | 软件导出整理后的 HTML，用户在浏览器中手动导入；已有书签如何处理以目标浏览器的导入行为为准。 |
| 扩展连接方式 | 安装配套扩展并授权，连接桌面软件，首次选择用户配置、导入范围和处理规则后，自动读取并导入。 | 用户点击“应用到浏览器”，查看差异并确认，完成备份后通过扩展直接写回。 |

**操作约定：**

- 主入口分别为“导入书签文件”和“连接浏览器”；用户可先手动导入，以后再连接扩展，重新关联来源并处理重复项。
- 首次扩展连接时明确显示目标用户配置、导入范围和结果；后续可使用“刷新导入”读取最新书签，沿用重复防护和冲突处理规则。
- 自动导入不自动删除浏览器书签。修改、去重后的结果由用户执行写回，并保留 INT-09 的差异预览、备份和冲突处理。
- 持续跟随浏览器新增、修改和删除属于 INT-07 的同步能力，需单独开启并配置方向及删除规则；安装扩展不默认开启双向同步。
- 扩展未安装、未授权或断开连接时，本地管理与手动文件方式继续可用。

### 重复检测与整理

| 编号 | 功能 | 功能说明 | 优先级 |
| --- | --- | --- | --- |
| DUP-01 | 完全重复检测 | 按保存的完整 URL 字符串查找重复项，支持跨文件夹检测。 | P0 |
| DUP-02 | 分组展示重复项 | 每组显示标题、URL、路径和添加时间，便于判断保留对象。 | P0 |
| DUP-03 | 手动选择保留项 | 选择保留一项或多项，将其余项目移入回收站。 | P0 |
| DUP-04 | 批量保留规则 | 按最早、最新或指定文件夹优先生成保留方案，执行前预览。 | P1 |
| DUP-05 | URL 规范化检测 | 按可选规则比较主机名大小写、默认端口、末尾斜杠等差异，生成疑似重复候选。 | P1 |
| DUP-06 | 跟踪参数识别 | 识别 UTM 等常见跟踪参数，对照展示原 URL 和建议 URL，确认后修改。 | P1 |
| DUP-07 | 重定向重复检测 | 联网检查不同地址是否跳转到相同页面，并标注时间和检测条件。 | P2 |
| DUP-08 | 相似标题检测 | 结合标题相似度和域名，查找可能重复的网页。 | P2 |
| DUP-09 | 重复文件夹检测 | 查找同层级同名文件夹，预览子项和冲突后合并。 | P1 |
| DUP-10 | 空文件夹清理 | 查找空文件夹，预览后批量移入回收站。 | P0 |

**规则建议：**完全相同 URL、规范化后相同 URL、重定向相同页面和内容相似，应作为不同类型展示。相同 URL 出现在不同文件夹中可能是用户有意分类，默认由用户决定是否保留。

规范化不直接改写原始 URL。路径大小写、末尾斜杠、查询参数和片段可能影响页面含义；跟踪参数识别和去重均先生成建议。删除前显示保留项、待移除项和影响数量，执行后可通过回收站恢复。

| --- | --- | --- |
| 尚未检测 | 未检测 | 加入检测任务。 |
| 当前请求成功 | 可访问 | 保留检测时间；结果不代表已验证页面内容或登录后可用性。 |
| 存在 301 / 308 跳转 | 永久重定向 | 查看跳转链与最终结果；符合地址更新规则时建议更新。 |
| 存在 302 / 307 跳转 | 临时重定向 | 默认保留原地址，可查看目标；确认属于稳定迁移后可手动更新。 |
| 存在 303 或永久、临时混合跳转 | 其他 / 混合重定向 | 展示各跳类型与最终结果，人工判断是否更新。 |
| 返回 404 或 410 | 疑似失效 | 浏览器复查、重试或手动处理。 |
| 返回 401、403 或遇到登录墙 | 需要复查 | 说明访问限制，不直接判定为可删除。 |
| 超时、DNS 失败或网络异常 | 检测异常 | 展示错误原因，支持重试。 |
| 命中排除条件或不支持协议 | 已跳过 | 显示跳过原因，允许调整范围。 |

首版检测即应设置合理的并发、超时和响应大小上限；P1 主要增加可配置项和更细的策略。默认检测范围建议为 HTTP / HTTPS，其他协议先标记为不支持或跳过。

#### 重定向标记与地址更新

**展示规则：**重定向作为独立标记和筛选条件，同时保留最终访问结果。例如 `302 → 200` 展示“临时重定向 · 最终可访问”，`301 → 404` 展示“永久重定向 · 最终疑似失效”。自动跟随跳转后，不能只保存最后的 200 而丢失跳转信息，也不能仅因存在跳转就判定书签失效。混合链优先标记为“混合重定向”，其他链按实际包含的类型展示。

HTTP 语义中，301 / 308 表示永久迁移，302 / 307 表示临时跳转；临时跳转的后续请求应继续使用原地址。因此，“跳转后的地址”不默认等于“适合长期保存的地址”。[HTTP 重定向规范](https://www.rfc-editor.org/rfc/rfc9110.html#name-redirection-3xx)

| 情况 | 默认处置 |
| --- | --- |
| 全部跳转均为 301 / 308，最终地址可访问 | 列为建议更新项，预览原地址和新地址，核对仍为原书签所指内容后确认更新。 |
| 302 / 307 临时跳转 | 保留原地址；用户确认是网站迁移、短链接展开等稳定目标后，可手动选择更新。 |
| 303 或包含临时跳转的混合链 | 保留原地址，不将整条链的最终地址直接列为建议更新项。 |
| 跳转到登录页、验证页、地区或语言选择页，或目标含临时令牌、签名及有效期 | 提示需要复查，默认保留原地址；最终返回 200 也不据此推荐替换。 |
| 跳转循环、超过跳转上限、缺少或无法解析目标地址，或最终地址访问失败 | 展示具体原因与已取得的跳转链，不推荐更新，允许浏览器复查或重试。 |

检测记录保留原地址、每一跳地址与状态码、最终地址、最终访问结果及检测时间。登录页、临时参数和内容对应关系的自动识别只能提供线索，无法确认时由用户复查。

地址更新由用户主动执行，支持逐项选择和批量预览，不因检测完成而自动覆盖书签。执行前重新核对书签 URL 是否仍与检测时一致；已被编辑的项目跳过并提示重新检测。更新保留原地址和新地址，纳入 EDT-12 约定的撤销范围；批量修改前完成备份。更新后如出现重复项，进入重复检测流程，由用户决定是否合并。

#### 后台检测与界面响应

开发要求：检测进行时，用户仍能滚动列表、输入搜索词、切换文件夹及操作暂停和取消。网络请求、数据解析和大量结果处理应在后台执行，界面不等待整个检测任务结束后才响应。

| 工作 | 执行位置建议 |
| --- | --- |
| 发起任务和操作按钮 | 前端提交范围与配置，快速取得任务标识并展示状态。 |
| 网络检查与重试 | Go 后端以有限并发执行，统一管理超时、跳转、速率限制及取消。 |
| 大批量整理和结果保存 | 本地后端处理去重、排序等计算，批量保存检测结果。 |
| 列表和进度展示 | 前端按批次接收进度和变化，只更新相关行，列表只渲染可见部分。 |

**技术选择建议：**批量链接检测优先由 Go 后端执行。复用 HTTP Client / Transport，并使用请求 context 处理取消；Go 官方支持这些对象在多个 goroutine 间并发复用。[Go HTTP 文档](https://pkg.go.dev/net/http)

前端 fetch 本身是异步的，但普通网页环境中的跨站请求受 CORS 限制，不能将跨域失败当成链接失效；no-cors 的不透明响应也不能用于可靠读取真实状态和页面内容。前端仍可通过本地接口或桌面通信桥启动任务、查询结果。[Fetch 文档](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API)、[CORS 说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)、[请求模式说明](https://developer.mozilla.org/en-US/docs/Web/API/Request/mode)

**任务执行规则建议：**

- 使用有界任务队列和固定数量的工作协程，不为全部书签一次性创建无限请求；分别限制全局并发和单域名并发。
- 试运行可从总并发 20、单域名并发 2、单次请求超时 10 秒、临时错误最多重试 1 次开始，按真实网络与测试结果调整；这些数值不代表性能保证。
- 保留有限重定向、响应大小限制和按条件 HEAD / GET 回退；请求完成后及时关闭响应体，避免网络资源长期占用。
- 暂停停止领取新任务，已发出的请求按约定完成；取消通过 context 通知进行中的请求并停止后续调度和重试，保留已完成结果。
- 检测结果进入有界缓冲并批量保存，避免每条结果单独触发数据库写入或界面全量刷新；界面刷新合并不应丢失检测记录。
- 进度和行变化可先按 100 至 200 毫秒合并更新，并限制单批大小；结束时刷新最后一批，结果较多时分页读取。
- 结果携带任务和书签库标识，切换库或取消旧任务后，不把旧事件混入当前界面；界面断开后可重新读取已保存的任务状态。
- 前端避免在每个完成回调里重新排序、筛选或渲染整库；大规模计算放在后端，必要的前端计算再考虑 Worker 分担。

**响应验收建议：**先以 1 万条书签的混合测试集验证并发检测，包含慢响应、超时、同域名集中和批量快速返回等情况。初始目标可设为常用操作在 200 毫秒内显示反馈；暂停或取消的按钮反馈与网络请求实际收尾分别计时。记录测试机器、界面版本、并发配置、交互延迟及内存变化，再确定最终规模和响应指标。以上为待实测的开发目标。

暂停和取消应说明对正在执行的请求如何处理。首版“继续”指当前任务内继续执行；跨程序重启续跑属于另行确定的范围。检测联网会访问书签对应站点，应在启动任务前清楚展示范围；检测结果不会自动触发删除。

#### 整理结果写回浏览器

使用示例：从本机浏览器读取书签，在管理器中修改标题、移动目录或去重，点击“应用到浏览器”，将确认后的结果直接写回，无需用户手动清空书签并重新导入文件。

**写回流程建议：**

1. 连接并确认目标浏览器及用户配置，记录原始书签快照和来源对应关系。
2. 在管理器中整理书签，保留本次编辑、移动、新增和删除的记录。
3. 写回前重新读取浏览器当前书签，与原始快照及本地整理结果比较，识别整理期间浏览器发生的变化。
4. 预览新增、修改、移动和删除项及数量；冲突项由用户选择保留浏览器内容、应用本地修改或跳过。
5. 备份目标范围内可读取的书签数据，用户确认后执行；备份失败则停止写回。
6. 完成后重新读取目标范围进行核对，展示成功、失败、跳过和未完成项，提供处理记录及恢复入口。

| 模式 | 行为 | 数据范围 |
| --- | --- | --- |
| 应用本次整理变更 | 将本次确认的修改和去重结果写回，作为默认模式。 | 保留不属于本次操作的书签，包括整理期间新收藏且未与本次修改冲突的内容。 |
| 替换指定范围书签 | 使选定文件夹或可编辑范围与管理器中的目标结果一致。 | 必须预览将被移除的全部项目并单独确认；范围外书签和不可修改节点保持不变。 |

**实现路径建议：**优先通过配套浏览器扩展调用书签接口，并与桌面程序建立本地通信。Chrome 提供书签增删改和移动接口、Native Messaging；Edge 支持 bookmarks 扩展接口，Firefox 也提供书签操作接口。各浏览器仍需分别适配和验证。[Chrome 书签接口](https://developer.chrome.com/docs/extensions/reference/api/bookmarks)、[Chrome 本地通信](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[Edge 接口支持](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/api-support)、[Firefox 书签接口](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Work_with_the_Bookmarks_API)

未安装扩展或扩展连接不可用时，继续提供手动 HTML 导入导出和本地整理；界面展示连接状态及重新连接入口。重新连接后先检查来源变化，再刷新导入或生成写回预览。

**写回规则建议：**

- 来源对应关系应包含浏览器、用户配置和书签标识。仅 URL 相同不能证明是同一个书签；HTML 导入等缺少可靠对应关系的来源，先重新关联并确认差异。
- 写回前重新检查目标变化；执行中发现额外变化时暂停并刷新预览，不将一次读取视为已锁定浏览器数据。
- 批量写回可能部分成功，需记录已完成操作并复核后再重试；不能将多次接口调用当作一次整体事务，也不能盲目重复执行删除。
- 书签栏等系统节点及受管理的只读项目按浏览器权限处理，不承诺可删除或替换。标签、备注、检测记录等仅写回目标浏览器明确支持的字段，其余保留在本地库。
- 如果目标书签参与浏览器自身的云端同步，写回的修改和删除可能传播到其他设备；不能承诺一次本地写回已锁定或完成所有设备同步。Chrome 还可能同时存在本地和账号书签，需展示实际目标范围。[Chrome 书签同步范围说明](https://developer.chrome.com/blog/bookmarks-sync-changes)
- 恢复前也应比较浏览器的最新变化，避免覆盖恢复点之后新增的内容。备份应说明实际保留的字段，以及恢复时书签标识、时间等信息是否能够保留。
- 手动写回不自动开启持续双向同步。若将直接整理浏览器书签作为主要体验，应将本机直接导入、写回和必要的扩展连接一起纳入版本规划。

**验收场景建议：**编辑标题、移动目录及去重后可直接在浏览器中看到相应结果；默认模式保留整理期间新收藏的无关书签；替换模式只影响已确认范围；备份失败、权限不足、连接中断和并发修改均有明确处理结果，部分成功后可核对和恢复。

| SYN-06 | 同步记录 | 展示上次同步时间、结果、错误和待处理冲突。 | P2 |
| SYN-07 | 云端账号服务 | 有明确需求时增加账号或自建服务，本地功能继续独立使用。 | P2 |

**规则建议：**同步备份文件与多设备合并编辑应分别设计。将正在使用的数据库放入同步目录，不视为已具备可靠的多设备同步能力。同步失败或离线时继续允许本地使用；同步范围应明确是否包含配置、图标和网页归档。

### AI 与自动整理

| 编号 | 功能 | 功能说明 | 优先级 |
| --- | --- | --- | --- |
| AIA-01 | AI 自动摘要 | 根据可用的标题、描述或正文生成摘要，帮助判断是否保留页面。 | P2 |
| AIA-02 | AI 自动打标签 | 提出标签建议，用户确认后应用。 | P2 |
| AIA-03 | AI 分类建议 | 推荐文件夹或主题分类，确认后执行移动。 | P2 |
| AIA-04 | 自然语言搜索 | 无需记住网站名称，用“找出收藏里的所有 icon 图标网站”“以前收藏过的 C++ 网络库”等描述查找相关书签，与 SRC-11 共同实现。 | P2 |
| AIA-05 | AI 去重建议 | 辅助识别不同 URL 的相近内容，人工确认后处理。 | P2 |
| AIA-06 | 模型配置 | 支持按需选择本地模型或第三方 API，明确发送的数据内容。 | P2 |
| AIA-07 | 成本与隐私控制 | 预估调用数量，限制批量任务和调用额度，允许关闭云端上传。 | P2 |
| AIA-08 | AI 相似网站推荐 | 右键单个网站书签，结合网站用途和联网检索推荐类似网站，展示推荐理由、来源和已收藏状态，支持选择后加入书签库。 | P2 |

**规则建议：**摘要和建议与用户原始信息区分展示；应用标签、移动或清理前可预览和确认。网络或模型不可用时，基础管理、关键词搜索和手动整理仍可使用。发送 URL、标题、描述或正文的范围应由用户明确选择。

#### AI 自然语言搜索

使用示例：用户想找一个曾经收藏的 icon 图标网站，却忘了名字，输入“找出收藏里的所有 icon 图标网站”，查看书签库中符合用途的相关网站。

1. 在搜索入口选择 AI 搜索，输入自然语言需求；默认搜索当前书签库，也可限定文件夹范围。
2. 理解“icon”“图标”“SVG 图标”“图标素材库”等相关表达，综合标题、URL、标签、备注、已有网页描述或摘要判断用途。
3. 综合关键词匹配和内容含义查找候选，标题中没有“icon”的图标网站也可进入结果。
4. 以书签列表展示网站名称、URL、所在文件夹和匹配理由，并区分明确匹配与可能相关的候选。
5. 用户可继续补充“只要免费资源”“排除图标编辑工具”等条件，打开网站、定位原书签，或使用现有批量操作。

**搜索规则建议：**

- 目标是找全当前搜索范围内的相关书签，支持完整结果列表、结果数量和分页，不固定只展示前几条。
- 显示当前检索范围及可分析信息的覆盖情况；存在待分析书签、信息不足或任务尚未完成时提示可能遗漏，不宣称已找全。
- 每项结果必须对应当前书签库中的实际书签，匹配理由应依据已保存或已获取的信息，不能虚构未收藏的网址或网站功能。
- 对名称不明显的站点，可使用已有描述和摘要辅助判断；信息不足时标记待分析，按用户设置补充网页信息或手动描述后重新检索。
- 免费情况、资源格式等限定条件有依据时再作为确定匹配；无法确认的结果单独标记，允许用户复查。
- 新增、修改、移动和删除书签后更新相关检索信息，避免持续展示旧路径、旧分类或已删除的书签。
- 按 AIA-06、AIA-07 的配置使用本地模型或第三方服务；可复用已分析的信息，不要求每次查询上传整个书签库。AI 不可用时保留普通关键词搜索，并明确说明当前搜索方式。

**验收场景建议：**测试库同时包含标题带“icon”的图标站、标题不带关键词但描述明确的图标站，以及用途不同的网站。查询后应能找回前两类相关书签，并给出依据；结果较多时可翻页查看。存在未分析项时显示覆盖不足，取消搜索不改变原始书签。

本功能用于找回已收藏的网站；查找尚未收藏的类似网站使用 AIA-08 相似网站推荐。

#### 相似网站推荐

使用示例：右键一个 icon 图标资源网站，选择“AI 推荐相似网站”，查找提供类似图标素材、图标库或图标搜索服务的网站。

1. 读取所选书签的 URL、标题和已有描述；信息不足时，可按用户设置获取网页介绍或补充需求。
2. 用户可补充“免费优先”“提供 SVG 图标”“相近图标风格”等偏好。
3. 结合联网检索查找候选网站，AI 比较其用途、资源类型和特点，生成推荐结果。
4. 每项展示网站名称、URL、简介、推荐理由、信息来源，以及是否已在当前书签库中收藏。
5. 用户可打开网站查看，或选择一项、多项加入指定文件夹；保存前检查重复项，允许修改标题和标签。

**推荐规则建议：**

- 推荐目标是发现外部的类似网站；与 SRC-11、AIA-04 在已有书签库中查找内容的功能分别定义。
- 默认只使用当前选中书签的必要信息，不上传整库书签；调用第三方模型或检索服务时遵循 AIA-06、AIA-07 的配置。
- 推荐 URL 应有检索或网站页面来源，不凭空拼接域名；简介、免费情况等信息缺少依据时标记为未核实。
- 展示链接检查状态和时间；遇到访问受限、超时等情况，沿用 CHK 的分类，不将它们直接认定为永久失效。
- 合并重复的推荐结果，标记或按用户选择隐藏已收藏网站；结果数量不足时按实际数量展示。
- 无网络、服务失败或无可靠候选时给出明确反馈，允许重试或调整偏好；取消推荐不改变书签库。

**验收场景建议：**右键图标资源站后，能获得带实际来源和相似理由的候选网站；重复候选和已收藏状态可识别；只保存用户选中的结果，关闭推荐窗口不新增书签。

#### 前端技术与视觉方向

**已确定：**桌面工程使用 Go + Wails v3.1.0；前端使用 React + TypeScript + Vite + pnpm，UI 组件采用 Radix Themes；不采用 Google Material 3 风格。界面以简洁的桌面书签工具为目标，按实际需要选择组件。

**工程约定：**业务布局和少量样式调整使用普通 CSS 或 CSS Modules，Tailwind CSS 不作为必需依赖。前后端通信使用 Wails 提供的服务绑定和事件机制；当前仅初始化工程，尚未注册业务服务或实现功能。

**组件使用原则：**采用 Radix Themes 提供的预设样式和主题配置，统一管理强调色、灰阶、圆角和控件尺寸。优先使用现有组件与主题配置，业务专用布局单独实现；需要更底层的交互定制时再评估 Radix Primitives。

首版仅按界面需要引入按钮、输入框、复选框、右键菜单、下拉菜单、对话框和提示等基础组件。文件夹树、书签列表和详情面板围绕已有业务设计；不因组件库提供了某个组件就增加界面功能。

视觉建议：延续左侧文件夹树、中间书签列表、右侧详情的结构；使用中性色背景、细分隔线、克制的圆角和少量强调色，优先保证标题、路径、状态和选中项清晰。工具栏紧凑，详情栏可收起，减少装饰性大卡片和过度动画。浅色与深色主题共享统一的颜色、间距和状态规则。

性能要求独立于 UI 库：大量书签仍需列表虚拟化、分页和结果批量更新，避免检测结果导致整棵树或整张列表反复渲染。选择 React 或某个组件方案不代表已经满足不卡顿要求。

选型依据：[Radix Themes 官方介绍](https://www.radix-ui.com/themes/docs/overview/getting-started)。

## 关键操作流程

### 首次建立书签库

1. 选择新建空库、导入书签文件或连接浏览器扩展。
2. 设置名称和保存位置。
3. 手动方式选择 HTML 文件；扩展方式完成安装授权并选择浏览器用户配置。设置导入范围、目标文件夹和冲突规则，查看预览。
4. 确认后执行导入；扩展方式自动读取选定范围并应用规则，两种方式均展示导入报告。
5. 进入书签列表，开始搜索和整理。

### 整理重复书签

1. 选择整个库、文件夹或选中范围，执行检测。
2. 按组查看重复类型、URL 和原始路径。
3. 手动选择保留项，或使用已启用的批量保留规则。
4. 预览待保留和待移除项目；批量修改前完成备份。
5. 确认后将待移除项放入回收站，展示处理结果并提供恢复入口。

### 检测与复查异常链接

1. 选择检测范围，查看将访问的链接数量和检测策略。
2. 启动任务，持续显示进度，允许暂停或取消。
3. 按结果分类查看异常原因与检测时间；重定向单独筛选，展示跳转类型和最终访问结果。
4. 对疑似异常项用浏览器打开、重新检测或手动修正；对重定向查看原地址、跳转链、最终地址和更新建议，临时跳转默认保留原地址。
5. 用户预览并确认后更新选中 URL 或移入回收站；地址更新保留原地址供约定范围内撤销，结果保留在当前支持的范围内。

### 导出与恢复

1. 选择目的：导回浏览器，或备份本工具数据。
2. 选择范围、格式和保存位置，查看格式能保留的信息。
3. 导出后展示成功或失败结果。
4. 恢复时先验证备份、展示恢复范围和现有数据的处理方式。
5. 用户确认后执行恢复；需要覆盖时先备份当前数据，失败时保留可恢复版本。

| 场景 | 预期行为 |

| 更新重定向地址 | 全部为永久跳转且最终可访问的链可生成更新建议；登录跳转、临时签名地址及混合链默认保留原地址。预览确认后更新，已编辑项跳过，支持约定范围内撤销，出现重复项不自动合并。 |
| 暂停或取消检测 | 任务状态清楚；按约定停止后续工作，已完成结果可以继续查看。 |
| 导出浏览器文件 | 选定目标浏览器可导入对应文件，并恢复该格式支持的标题、URL 和目录。 |
| 备份与恢复 | 备份覆盖当前版本已支持的数据；恢复失败不留下无法继续使用且无可恢复副本的书签库。 |
| 大量书签操作 | 在约定规模下并发检测时，列表滚动、搜索、切换文件夹及暂停或取消均可响应；慢站点和批量结果返回不阻塞界面，记录实际交互延迟与资源占用。 |
