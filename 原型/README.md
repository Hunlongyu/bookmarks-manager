# 书签管理器交互原型

直接用 Chrome、Edge 或 Firefox 打开 [index.html](index.html)。页面已经包含脚本和样式，离线可用，无需启动 Go 或开发服务器。

使用实际 **React + Radix Themes** 组件，包括按钮、标签页、表单、弹窗、下拉菜单、右键菜单和表格。采用 TypeScript、Vite、pnpm 构建，图标来自 Radix Icons。默认浅色，可切换深色。

仅面向桌面端，不制作手机界面。窗口可自由调整大小，没有固定或最小尺寸要求；左侧导航和详情随窗口伸缩，工具栏和表单按可用空间换行。工作区标题、搜索、选择与列表共同滚动，底部计数与详情入口固定。空间不足时详情改由底部“查看详情”打开弹窗；宽窗可收起并重新展开详情栏。

## 建议体验路径

1. 打开后直接进入书签工作区，点击“导入书签”选择浏览器或 HTML 文件。导入后返回列表；导入页的“查看完整示例”可载入演示数据。
2. 如需体验 AI，在“设置”中点击“填入演示配置”与“测试连接”。无需 AI 时可直接检查可访问性。
3. 点击“检查书签”，选择规则检查或 AI 分析，体验暂停、继续、取消和异常重试。
4. 查看修复建议：地址变更默认不选，分别打开原地址与建议地址，核对页面后勾选确认。跳转链与响应状态均为演示证据；标题与图标建议独立分组。目录整理先看目标树与“已选 / 建议移入”计数，再按目录或逐条选择，展开分类依据后应用。需要恢复时可使用回收站，或在“备份与恢复”中选择相应备份。
5. 搜索“所有 icon 图标网站”，或右键 Lucide，选择“AI 推荐相似网站”。
6. 在左侧选择“写回浏览器”，体验关闭预检、备份、覆盖和部分失败；或选择“导出 HTML”下载书签。成功后显示本次报告，也可点击“完成整理”进入报告；报告不设常驻导航入口。
7. 在“设置 → 软件更新”体验检查、下载、校验和模拟重启。自升级安排在开发计划的最后阶段。

界面只保留统一工作区，不再提供引导模式、步骤条或模式名称。“新建”只负责添加书签与新建文件夹；来源目录旁的“目录操作”提供新建、合并与清理空文件夹。目录行悬停或键盘聚焦时可使用更多按钮，也保留目录和书签的右键菜单。合并可保留全部、跳过重复或逐项决定。

检查或分析完成、取消后，仅在书签工作区与检查结果页保留简短状态和处理入口，进度条收起，其他页面不占位。

## 可实际操作与演示边界

| 类型 | 原型行为 |
| --- | --- |
| 页面内实际操作 | 选择、编辑、移动、排序、合并、去重、回收恢复、筛选、创建备份、自动加载备份列表与选择恢复。 |
| HTML 导入导出 | 在页面内解析浏览器书签 HTML，保留目录层次；输出真实可下载的 Netscape 书签 HTML。当前原型接收 HTTP/HTTPS 书签，单文件上限 20 MB。 |
| 浏览器操作 | 全部为示例数据与状态演示，不读取、关闭或覆盖真实浏览器。 |
| 检查、代理、AI | 全部使用固定样例与计时状态，不发送请求、不验证真实密钥、不消耗 token。外部网站链接只有点击后才由浏览器打开。 |
| 自升级 | 使用虚构版本演示流程，不下载更新或替换程序。 |
| 保存范围 | 工作区和演示配置保存在页面内存；刷新后工作区从空白开始。备份使用浏览器本地存储模拟固定目录，在同一浏览器重新打开本页时自动加载列表，恢复仍由用户选择。“结束会话”保留页内配置及备份；清除浏览器存储或使用不同浏览器会影响演示备份的可见范围。 |

备份页展示固定路径 `%APPDATA%\BookmarksManager\backups`，没有任意备份文件打开、下载或另存目录的操作。该路径只表示产品约定，原型不会访问真实 AppData；HTML 导出仍可独立下载。

实际产品中的 AppData 持久保存、Go 并发、浏览器兼容与 AI 服务均按开发计划后续实现。这个原型不能作为一万条性能或真实浏览器写回验收证据。

## 修改与构建

在仓库根目录运行：

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend prototype:dev
```

开发入口为 `http://127.0.0.1:5178/app.html`。原型复用 `frontend` 中的依赖，但源码与输出独立放在本目录。

```powershell
pnpm --dir frontend prototype:check
pnpm --dir frontend prototype:build
node 原型/scripts/verify.mjs --capture
node 原型/scripts/verify-ui.mjs
```

两个验证脚本使用已安装的 Microsoft Edge 进行无头浏览器验证。原有流程结果与截图写到 `.impeccable/review/`，UI 回归写到 `.impeccable/review/ui-fixes/`。UI 回归覆盖 760×500、900×450、900×600、1100×720、1440×900 和 1920×1080 六个桌面窗口样本，以及共同滚动、固定底栏、详情切换、菜单焦点恢复、地址复核与 AI 目录树选择；这些是验证样本，不是默认或最小尺寸，也不代表任意窗口均已验收。构建脚本将 Vite 的临时产物内联成 `index.html`；修改源码后需要重新构建，直接打开的 HTML 才会更新。

| 文件 | 用途 |
| --- | --- |
| `app.html`、`src/main.tsx` | Vite 与 React 入口。 |
| `src/App.tsx`、`src/styles.css` | 桌面布局、常驻导航、主题与样式。 |
| `src/Workspace.tsx`、`src/Operations.tsx` | 书签列表、详情、编辑、检查与清理交互。 |
| `src/Flow.tsx`、`src/Settings.tsx`、`src/AI.tsx` | 导入输出、设置更新、AI 整理推荐。 |
| `src/model.ts`、`src/state.tsx` | 演示数据、页面内状态和 HTML 处理。 |
| `scripts/build.mjs`、`scripts/verify.mjs`、`scripts/verify-ui.mjs` | 离线打包、交互验证与 UI 修复回归。 |

需求和阶段安排见[功能清单](../docs/书签管理器功能文档.md)与[开发计划](../docs/新版开发计划.md)。
